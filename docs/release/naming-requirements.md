# Naming requirements

**DO NOT PUBLISH — PUBLICATION APPROVAL REQUIRED**

Require an English, short, readable brand with valid Python import spelling, distinct
GitHub discoverability and CLI command, and an available PyPI distribution family.
Avoid confusion with Microsoft Agent Framework and avoid commerce-specific branding:
Core is generic. Check normalized PyPI names (case and hyphen/underscore/dot aliases),
imports and executables together. A search is not a reservation or ownership grant.

The user selected `orivane` for the brand and accepted the documented GitHub
same-name risk. These original family patterns now use that root:

| Surface | Pattern |
| --- | --- |
| Repository | `orivane` |
| Core distribution | `orivane-core` |
| Backend distribution | `orivane-backend-pydantic` |
| CLI distribution | `orivane-cli` |
| Optional commerce package | `orivane-commerce` |
| Future plugin distribution | `orivane-plugin-<capability>` |
| Python modules | `orivane_core`, `orivane_pydantic`, `orivane_cli` |
| Executable | `orivane` |

Prefer a single memorable root across this family. Future commerce/plugin patterns
are naming capacity, not implemented packages. `orivane-commerce` is a future name
only. Refresh registry checks before any separately authorized publication.
