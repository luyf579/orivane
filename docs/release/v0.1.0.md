# Orivane v0.1.0

Release notes prepared on 2026-09-28 for final Maintainer review. The repository
remains PRIVATE; v0.1.0 is not yet published to PyPI, tagged or released on GitHub.

## What is Orivane?

Orivane is a small, typed Python runtime for backend-adaptable AI agents, sessions,
workflows, observability and local developer tooling. Application code can depend
on the AgentBackend contract while the composition root selects a backend/model.
Orivane v0.1.0 is an early release.

## Highlights

- Typed AgentBackend, RunRequest, RunResult and validated ToolDefinition contracts.
- PydanticAI backend with explicit budgets, cancellation and borrowed-model ownership.
- Versioned SessionState and InMemorySessionRuntime with same-session ordering.
- Linear async Workflow steps and basic boolean branches.
- Structural logging and OpenTelemetry spans with privacy defaults.
- Offline CLI init, validate, run and trace commands.
- Three synchronized distributions, Python 3.11/3.12 support and MIT licensing.

## Install

Once v0.1.0 is published to PyPI, run in a new project directory in PowerShell:

```powershell
pipx install orivane-cli
orivane init demo
cd demo
orivane validate .
"hello" | orivane run .
"hello" | orivane trace .
```

Alternatively, use `pip install orivane-cli` inside a Python environment. The CLI
installs matching `orivane-core==0.1.0` and `orivane-backend-pydantic==0.1.0`.
The starter uses offline TestModel and requires no provider credential.

## Core capabilities

Agent runs return typed outputs and replacement session state only on success.
Tool definitions validate arguments before calling application tools. Errors and
cancellation propagate; there is no automatic whole-run retry or side-effect rollback.
Sessions require explicit creation and enforce capacity. Workflow composition uses
named steps and selects one branch at a time. The CLI validates configuration without
importing application code and prints a local structural trace on demand.

## Compatibility

Python 3.11 and 3.12 are tested. Core and backend include PEP 561 type markers.
PydanticAI (`pydantic-ai-slim`) and pydantic-graph are pinned to 2.48.0.
OpenTelemetry API/SDK stay at the verified 1.44.0 resolution, with SDK-required
semantic conventions 0.65b0 as a transitive dependency. External dependencies do
not change in this release preparation.

Public APIs follow semantic versioning from v0.1.0 onward, while 0.x minor releases
may intentionally evolve the API with release notes. No production-readiness or
permanent API-stability guarantee is made.

## Known limitations

- Only the PydanticAI backend is currently implemented.
- PydanticAI is pinned to 2.48.0.
- Sessions are in-memory.
- Same-session serialization applies only within one process and one event loop.
- Workflow supports linear steps and basic branching only.
- No durable workflow execution.
- No persistent memory.
- No multi-agent orchestration.
- No Commerce package yet.
- No plugin ecosystem yet.
- No real-provider certification matrix yet.

## Security and privacy defaults

Framework logs, spans and CLI structural trace exclude prompts, contexts, outputs,
tool arguments/results, session payloads and exception messages. The CLI still
prints the application result separately from its structural trace. PydanticAI
content capture is disabled. No exporter or telemetry upload is configured by default.
Applications own logging/exporter configuration, model resources, side effects and
protection of native session snapshots, which can contain sensitive data.
See [SECURITY](../../SECURITY.md) and [observability](../architecture/observability.md).
